# Build LOCUS from your own corpus

Nothing in the benchmark is specific to Gu et al.'s data. The harness reads a
corpus through one documented interface — see [schema.md](schema.md) — and
every build verb takes `--corpus DIR` to read it instead of `$LOCUS_DATA_DIR`.
`locus.data.adapters.gu2022` converts the upstream corpus into exactly that
shape, which is the demonstration that the contract is sufficient rather than
merely designed.

`locus.data.ingest` is the module that reads it:

    <root>/
        contexts.jsonl                 one JSON object per line
        papers.jsonl                   one JSON object per line
        splits/{train,val,test}.json   JSON array of context_id strings

The field-by-field contract for `contexts.jsonl` and `papers.jsonl` -- what
each column means, and why `raw` and `authors` matter beyond their type -- is
in [schema.md](schema.md); it is pinned to the code and is not repeated here.

### Validate, then build

```bash
.venv/bin/locus ingest /path/to/corpus          # exit 0 iff there are no problems
```

Every problem it reports names the offending id and the rule it broke, and
every check runs to completion rather than stopping at the first violation:
ids unique, every `refid` resolvable, `masked_text` non-empty with exactly one
`TARGETCIT`, `authors` (where present) a JSON array, no citing paper split
across two splits -- the leakage check -- and the `raw`/`masked_text`
alignment rate.

```bash
export LOCUS_WORK_DIR=/path/to/work             # LOCUS_DATA_DIR is not needed
.venv/bin/locus build pipeline    --corpus /path/to/corpus --split test
.venv/bin/locus build graph       --corpus /path/to/corpus
.venv/bin/locus build embed-inputs --corpus /path/to/corpus --split test
.venv/bin/locus embed  --input  $LOCUS_WORK_DIR/embed_inputs_test.parquet \
                       --output $LOCUS_WORK_DIR/embeddings_test.parquet
.venv/bin/locus build export --split test
.venv/bin/locus build export --split test --verify
.venv/bin/locus verify --export $LOCUS_WORK_DIR/export \
    --embeddings $LOCUS_WORK_DIR/embeddings_test.parquet \
    --graph      $LOCUS_WORK_DIR/cocitation_train.npz
```

`--verify` re-reads the export and recomputes the null controls from the
exported JSONL alone, and `locus verify` recomputes the headline result the
same way the paper's number was produced. Neither reads `$LOCUS_DATA_DIR` at
any point.

Two things a smaller corpus usually has to change:

  - **`--pool-size`.** A pool of *k* needs *k*-1 distractors from OTHER
    locations of the same citing paper. A corpus with fewer references per
    paper than Gu et al.'s cannot fill 10, and every context would be dropped
    as `too_few_distractors`. The chance floor is H_k/k and moves with *k*, so
    the export publishes the floor of the pools it actually wrote.
  - **the two Gu-calibrated gates.** The 40-85% hard-fraction band and the
    >= 30,000 headline floor describe the size and composition of one corpus,
    not the benchmark.

`tests/data/test_second_corpus.py` runs this whole path on a synthetic corpus
committed under `tests/data/fixtures/second_corpus/`, generated by a script
that shares no data and no code with the contract it exercises.
